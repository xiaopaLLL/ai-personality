# 问卷设计与结果简介

> 16 道情境题 · 4 个维度 · 8 种协作机体 · 约 3 分钟

这份文档说明两件事：问卷是怎么设计、怎么计分的；拿到结果后应该怎么读。题目与文案的代码位置、部署方式分别见 [README](../README.md) 和 [重新部署步骤](重新部署步骤.md)。

---

## 一、设计原则

- **日常情境**：16 道题都来自日常使用 AI 的具体场景（新工具、岔路、语气、文件夹、DDL 等），选项描述「你更可能怎么做」，不直接写「你是探索型」这类判断，减少「往好里选」的倾向。
- **主维度 + 少量次要分**：每道题声明一个明确的主维度，三个选项在主维度上是一正、一负、一中性（`+2` 或 `+1` / `−2` 或 `−1` / `0`）。部分选项额外带一个语义明确的次要维度 `±1`，例如「拿数据比较两套做法」在逻辑之外也体现结构，让相邻倾向也能被看见，但不会变成随意加权。
- **补偿下调**：每加一个次要 `+1`，就把该维一个原本 `+2` 的选项降为 `+1`；每加一个次要 `−1`，就把该维一个原本 `−2` 的选项降为 `−1`。这样每个维度的理论极值仍是 ±8，归一化与百分比公式保持稳定。
- **无对错**：每个维度的两端都写有优势和容易忽略的边界，8 种机体只是风格画像，没有能力高低、优劣或「更好的人格」。
- **趣味参考**：8 个原型是本次趣味分类的设计规则，没有用真实人群样本校准，不是科学人格量表，也不是心理诊断。
- **题量与节奏**：共 16 题，4 个维度各 4 题，约 3 分钟；每题 3 个选项，选项的正 / 负 / 中性位置已打散，避免固定顺序暗示答案。

## 二、四个维度

四个维度在代码里的顺序固定为 `drive / heart / order / role`：

| 维度 key | 维度 | 左侧（正分） | 右侧（负分） | 在测什么 | 题号 |
| --- | --- | --- | --- | --- | --- |
| `drive` | 驱动方式 | 探索派 E | 交付派 D | 被新可能点燃，还是被目标结果驱动 | q01–q04 |
| `heart` | 交互偏好 | 共情派 W | 逻辑派 L | 更需要被理解，还是更需要准确 | q05–q08 |
| `order` | 做事方式 | 结构派 S | 灵感派 I | 依赖流程方法，还是依赖临场灵感 | q09–q12 |
| `role` | 协作姿态 | 主导派 P | 副驾派 C | 习惯掌控方向，还是与 AI 随时换手 | q13–q16 |

- 原始分为 0 时，该维显示 `50 : 50` 的均衡状态，方向为空（数据里记作 `X`），不把中性悄悄归到某一端。
- 括号里的大写字母只用于数据留存（`profileCode`），不参与机体编号，前台不展示。

## 三、题库分布与题目结构

四个维度各 4 题，共 16 题，顺序固定：

| 题号 | 主维度 | 题号 | 主维度 |
| --- | --- | --- | --- |
| q01–q04 | 驱动方式 | q09–q12 | 做事方式 |
| q05–q08 | 交互偏好 | q13–q16 | 协作姿态 |

每道题由「题干 + 3 个选项」组成，并在代码里声明一个主维度 `dim`。三个选项在主维度上是一正、一负、一中性；部分选项还额外带一个语义明确的次要维度 `±1`。下面是从 `assets/js/questions.js` 摘出的两个真实结构示例。

### 3.1 示例一：驱动方式（q02，带次要维度）

```javascript
{
  id: 'q02',
  dim: 'drive',
  text: 'AI 的答案里突然冒出一条没想过的岔路，你会？',
  options: [
    { text: '顺着追问几轮，原题先等等，我想看看这条路通向哪儿。', scores: { drive: 2, heart: 1 } },
    { text: '先看能不能帮到当前目标；帮不上就先存着，继续办眼前的事。', scores: { drive: -1 } },
    { text: '先花两分钟问清它是什么，再决定追下去还是回到原题。', scores: { drive: 0 } }
  ]
}
```

第一个选项的主维度 `drive` 得 `+2`（探索端），次要维度 `heart` 得 `+1`：追岔路本身也意味着愿意多聊两句。

### 3.2 示例二：交互偏好（q05，负分主维度 + 次要维度）

```javascript
{
  id: 'q05',
  dim: 'heart',
  text: '向 AI 描述问题时，你的“接入暗号”更像哪一句？',
  options: [
    { text: '“我现在有点乱，先陪我把来龙去脉捋一捋。”', scores: { heart: 1 } },
    { text: '“我先把问题说完，你看看还缺什么信息，再决定怎么聊。”', scores: { heart: 0 } },
    { text: '“目标、已知条件和限制都在这儿，请按它们分析。”', scores: { heart: -2, order: 1 } }
  ]
}
```

最后一个选项在 `heart` 上偏逻辑端 `−2`，同时 `order` 次要 `+1`：按目标条件分析，通常也意味着更结构化的做事方式。

- 每题 `dim`（主维度）必填，用于题库分布校验与答题页的维度标签。
- 主维度一正、一负、一中性；正分可能是 `+2` 或 `+1`，负分可能是 `−2` 或 `−1`（补偿下调会让部分选项变成 ±1），中性固定 `0`。
- 次要维度每个选项最多一个、分值只能是 `±1`，且与主维度不同；全题库共 16 个次要分。
- 主维度的正 / 负 / 中性选项位置不固定，增删题目后仍要保持这些约束。
- 完整 16 题见 `assets/js/questions.js` 的 `SURVEY.questions`。

## 四、计分规则

1. **单题计分**：按所选项，把该选项 `scores` 里各维度的分值累加。每题有一个主维度，部分选项还带一个次要维度。
2. **主维度分值**：三个选项在主维度上分别是一正、一负、一中性；正分可能是 `+2` 或 `+1`，负分可能是 `−2` 或 `−1`，中性固定 `0`。
3. **补偿下调**：为了不让次要分把某个维度的理论极值撑大，每加一个次要 `+1`，该维就有一个原本 `+2` 的选项被降为 `+1`；每加一个次要 `−1`，该维就有一个原本 `−2` 的选项被降为 `−1`。因此四个维度的理论极值仍然都是 **−8 ~ +8**。
4. **维度求和**：每维 4 题，原始分 `s` 落在 −8 ~ +8（当前题库下四个维度都能取到 +8 和 −8）。
5. **归一化**：`x = s / 8`，每个维度归一化到 `−1 ~ +1`。
6. **展示百分比**：左侧百分比 = `round(50 + 50x)`，右侧百分比 = `100 − 左侧`。
   - 示例：`x = 0.75` → 左侧 88%，右侧 12%；`x = 0` → 50 : 50。
   - 0 分固定显示 50:50，不把中性悄悄归到某一端；左侧百分比天然落在 0 ~ 100。
7. **展示取整不参与分类**：四维条上显示的是四舍五入后的整数百分比；匹配机体时使用的是**未取整的 `x`**，不会用展示百分比反推分数。

> 主维度 `dim` 用于题库分布校验（每维恰好 4 题）和答题页的维度标签；实际计分仍按选项 `scores` 里各维度的分值累加，因此一个选项可以同时影响主维度和一个次要维度。

## 五、算例：(7, 6, 3, 2) → 机魂总调度

以 `tests/engine.test.mjs` 里的 M01 见证答案（`WITNESSES.M01`，一套完整 16 题作答）为例，四维原始分为 `(7, 6, 3, 2)`（顺序：驱动方式 / 交互偏好 / 做事方式 / 协作姿态）。这些分数里已经包含主维度分和少量次要分：例如驱动方式由四道驱动题的 `+2` 加上另一题里 `drive: −1` 的次要分，得 7；做事方式的 3 分里也混有多个 `order: +1` 的次要分。

归一化坐标：

```text
x = (7, 6, 3, 2) / 8 = (0.875, 0.75, 0.375, 0.25)
```

四维展示百分比：

| 维度 | 原始分 | 归一化 x | 左侧百分比 | 右侧百分比 |
| --- | --- | --- | --- | --- |
| 驱动方式 | 7 | 0.875 | 94% | 6% |
| 交互偏好 | 6 | 0.75 | 88% | 12% |
| 做事方式 | 3 | 0.375 | 69% | 31% |
| 协作姿态 | 2 | 0.25 | 63% | 37% |

把这个坐标与 M01「机魂总调度」的原型坐标 `(1, 0.75, 0.5, 0.25)` 代入距离公式：

```text
D = ((0.875−1)² + (0.75−0.75)² + (0.375−0.5)² + (0.25−0.25)²) / 4
  = (0.015625 + 0 + 0.015625 + 0) / 4
  = 0.0078125
```

距离不是 0：题目分值经过补偿下调后，可达的原始分组合无法恰好等于原型坐标的每一维（例如 `0.5` 对应原始分 4，而这套作答的做事方式是 3）。但 `0.0078125` 仍然是八种机体里最小的距离，所以结果是 **M01 机魂总调度**，并且是唯一匹配、没有并列。四维方向都是左端，`profileCode` 为 `EWSP`（第一位驱动方式、第二位交互偏好、第三位做事方式、第四位协作姿态）。

注意：`94%`、`69%` 等是展示取整的结果；如果反过来用 `0.94` 去算距离，会得到不同的值。匹配使用的是未取整的 `x`，这也是「展示值不参与分类」的实际意义。

## 六、八种协作机体

八种机体是四维空间里的八个原型坐标，顺序固定为 `drive / heart / order / role`。八个原型等范数（每一维的绝对值集合都是 `{0.25, 0.5, 0.75, 1}`），并组成四对相反画像。

| 内部编号 | 机体 | 四维坐标（驱动 / 交互 / 做事 / 协作） | 相反画像 | 一句话 |
| --- | --- | --- | --- | --- |
| M01 | 机魂总调度 | `1 / 0.75 / 0.5 / 0.25` | 外脑快修侠 | 脑洞已经接入，先把大家的频道对齐。 |
| M02 | 霓虹树洞 | `0.5 / 0.25 / -1 / -0.75` | 协议铸造师 | 先接住这句话，下一步边聊边长出来。 |
| M03 | 数据潜航员 | `0.25 / -0.5 / 0.75 / -1` | DDL领航员 | 让 AI 先下潜，沿着证据链慢慢打捞。 |
| M04 | 义体拆解客 | `0.75 / -1 / -0.25 / 0.5` | 人机调音师 | 先拆开看看，再决定这块模块怎么接。 |
| M05 | 人机调音师 | `-0.75 / 1 / 0.25 / -0.5` | 义体拆解客 | 先听清这次要什么，再把人机声道调顺。 |
| M06 | DDL领航员 | `-0.25 / 0.5 / -0.75 / 1` | 数据潜航员 | 终点先标出来，航线允许途中改。 |
| M07 | 协议铸造师 | `-0.5 / -0.25 / 1 / 0.75` | 霓虹树洞 | 接口先约好，再让任务一段段接起来。 |
| M08 | 外脑快修侠 | `-1 / -0.75 / -0.5 / -0.25` | 机魂总调度 | 先处理眼前这件事，方法够用就上手。 |

四对相反画像：M01 ↔ M08、M02 ↔ M07、M03 ↔ M06、M04 ↔ M05。

- 编号 M01–M08 只是数据库里的类别标识（`result_code`），前台的档案页、结果页和分享页都只显示机体中文名和人物图，不显示编号。
- 8 个原型的坐标和机体文案都写在 `assets/js/personality.js`；结果页的 `tagline / desc / strengths / watch / tips` 直接读取这些内容。

## 七、匹配规则

### 7.1 距离公式

把四维归一化坐标 `x` 和某个机体的原型坐标 `p` 比较，采用相同权重的平方距离：

```text
D(机体) = ((x1 − p1)² + (x2 − p2)² + (x3 − p3)² + (x4 − p4)²) / 4
```

取 `D` 最小的机体。公式里的 `x` 使用未四舍五入的归一化坐标；八个原型的范数相同，每一维权重相同。

### 7.2 并列

- 多个机体的最小距离**完全相同**时，全部保留为并列候选，数据里记下全部候选（`percents.match.candidates`）。
- 页面会先展示其中一个（按机体列表顺序），并明确说明「只是并列候选之一，排列顺序不代表更准确」。
- 全中性作答（四维都是 0）是并列的极端情况：八种机体同样接近（`allNeutral = true`），页面会列出全部 8 个候选，并明确说明当前图片只是并列候选之一。

### 7.3 同时接近

最佳距离与次佳距离之差不超过 **1/16**（0.0625）时，页面额外提示「同时接近另一台机体」。这个阈值只是展示提示，不是置信度，也不改变最终展示的机体。

### 7.4 缺题与非法选项

- 试卷缺题、或选项下标非法（超出 0–2、非整数等），不算完成答卷：引擎标记 `complete = false`；前台不会出结果，会把用户带回未作答的题目。
- 记录里的 `answered / total` 可用来核对完成情况。

### 7.5 计分与匹配的设计校验

- 八个原型等范数、四对相反画像。
- 每种机体都有一份完整的 16 题「见证答案」能唯一命中它（见 `tests/engine.test.mjs` 里的 `WITNESSES`），说明 8 种机体都能被真实作答命中；这里不再列出 8 组答案序列，需要时直接看测试文件。
- 新计分下穷举全部可达四维总分，共 **50,021 种**；每一种都用独立实现的距离公式核对过，保证每个可达分布都能稳定落到某个机体。8 种机体全部可达，且每种都有上千种可达总分；并列候选与 1/16 近似提示都真实存在（不是理论上的极端情况）。
- 全部 16 题的作答组合数为 `3^16 = 43,046,721`；其中很多组合会得到相同的四维总分，所以去重后的可达总分是 50,021 种。

## 八、结果页怎么读

首页只有 8 个机体名称的**纯文字目录**，不展示人物图片；人物插画只出现在结果页大图、并列候选小图、对照机体缩略图和分享落地页。

结果页从上到下：

1. **机体档案**：人物大图、机体中文名、tagline、完整描述。图片来自 `assets/img/m0x.webp`。
2. **档案摘要**：显示「最强倾向」（偏离 50% 最大的维度及其占比）、「最均衡处」（最接近 50 : 50 的维度）、以及「情境样本」（16 道情境 / 4 个维度）。
3. **并列 / 同时接近提示**（仅在出现时显示）：说明候选、展示顺序不代表更准确；全中性时会特别说明图片只是并列候选之一。
4. **协作坐标（四维条）**：每条显示左右两极的名称与百分比，例如「探索派 88% / 交付派 12%」；某维为 0 时显示 `50 : 50` 与「均衡」。下方有一行说明：百分比是四舍五入的展示值，仅用于阅读，不参与机体匹配与分类。
5. **三块建议**：「偏好与优势」（3 条）、「容易忽略的边界」（2 条）、「可以尝试」（3 条），都来自该机体的 `strengths / watch / tips`。
6. **对照机体**：显示四维坐标相反的那一台机体的图片、名称、tagline 和一段互补说明（它站在你四维坐标的另一端，凑在一起时容易互补，但要先说好这一轮由谁定方向）。
7. **操作按钮**：复制结果文案、复制分享链接、系统分享（手机浏览器支持时出现）、再测一次。

分享相关的约定：

- 分享链接形如 `?type=machine-soul`，只包含机体 slug，不包含作答明细，也不含四字母代号。
- 分享落地页展示这台机体的图片、名称、tagline、描述和「四维坐标示意」（原型坐标，不是某个具体答题者的分数），点「我也测一次」可开始测试。
- 旧版 `?result=EWSP` 这类分享链接打开后显示「旧版 16 型结果已经下线」，不会展示旧类型，并引导开始新版测试。

## 九、数据里保留了什么

每次完成作答会向 Supabase 的 `ai_personality_responses` 表写一条记录（表结构见 `supabase/schema.sql`）。和匹配有关的内容：

- `result_code`：本次展示的机体编号，`M01`–`M08`，仅内部使用。
- `result_name`：对应的机体中文名。
- `scores`：四维原始分（−8 ~ +8）。
- `percents`：四维展示百分比；新版额外包含 `percents.match`：
  - `profileCode`：四维方向，如 `EWSP`；某维为 0 时该位是 `X`。
  - `display`：本次展示的机体编号。
  - `candidates`：距离并列的全部机体编号（全中性时是 8 个）。
  - `tie` / `allNeutral`：是否并列 / 是否全中性。
  - `near`：与最佳距离差 ≤ 1/16 的「同时接近」机体。
  - `bestDistance` / `secondDistance`：最佳 / 次佳距离。
- `answers`、`answer_detail`：每题所选选项的下标、选项文字与各维度分值（主维度 + 可能一个次要维度）。

为什么前台不显示编号和四字母代号：

- 新版的结果是 **8 种协作机体**，不是「四字母人格类型」。M01–M08 是内部类别标识，方便统计和以后调整；把编号或字母直接摆给用户，容易被误读成第九种分类或某种「人格代码」。
- 分享链接、结果页文案、复制出的文字都只使用中文机体名；旧版 16 型数据仍留在表里，用 `survey_version`（旧版记录与新版的版本号不同）和 `result_code`（新版为 M01–M08）区分，不影响新版统计。

## 十、局限说明

- 本测试是**趣味性的自我探索工具**，不是科学的人格测评，也不是心理诊断；8 种机体和匹配规则是设计出来的分类，没有经过真实样本的效度与信度校准。
- 四维百分比描述的是「这份问卷里的作答倾向」，不是人群中的百分位，也不代表能力高低。
- 同一个人的结果可能随最近的任务、心情和使用场景变化；距离接近时出现并列或「同时接近」是正常的。
- 不要用本测试的结果做招聘、筛选、考核或任何对他人能力的判断。
- 计分中的次要维度和补偿下调是设计选择，没有用真实样本估计权重，也不代表心理测量学意义上的加权量表。
