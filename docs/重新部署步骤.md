# 重新部署步骤（Windows PowerShell）

适用对象：以后改完题目、文案或图片，需要把新版重新发布到线上的人。
仓库：`https://github.com/xiaopaLLL/ai-personality`，默认分支 `main`。
线上地址：`https://xiaopalll.github.io/ai-personality/`。
发布方式：GitHub Pages 直接从 `main` 分支根目录发布，**没有构建步骤**，推送完等自动发布即可。

> 本文所有命令都在仓库根目录 `D:\xiaopaLLL\MBAItest` 下、用 Windows PowerShell 执行。

## 0. 这次升级改了什么（变更概览）

从旧版 16 型人格升级到新版 8 种「协作机体」，主要变化：

- **结果模型**：16 种旧类型 → 8 种协作机体（M01–M08 只是数据库内部类别标识，前台不显示编号和四字母代号）。
- **题库更新（v2.1）**：16 道题题面全部替换为新版文案（来源 `resources/questions_v2.1.md`）；每题主维度、选项分值结构、8 机体结果与数据字段均不变。`questions.js` 的 `meta.version` 升到 `v2.1`，新答卷 `survey_version = 'v2.1'`，旧记录仍保留原有版本号。
- **首页简化**：首屏的 8 张人物图改为**纯文字机体目录**（8 个中文名，用「/」分隔），首页 `<img>` 数量为 0，首屏页高从约 1930px 降到约 1160px，图鉴标题与留白也同步收紧；人物插画只保留在结果页大图、并列候选小图、对照机体缩略图和分享落地页。
- **前端 UI**：`index.html`、`assets/css/style.css`、`assets/js/app.js` 完全重写为暗绿 + 荧光绿档案风；结果页展示人物插画、四维条、三块建议和对照机体。
- **计分增强**：每题声明主维度，三个选项在主维度上是一正、一负、一中性（`+2` 或 `+1` / `-2` 或 `-1` / `0`）；部分选项额外带一个语义明确的次要维度 `±1`，并通过「补偿下调」保证四维原始分范围仍是 −8 ~ +8。`x = s / 8`、`round(50 + 50x)` 的归一化与百分比公式不变，结果页结构、分享链接和数据字段都不受影响。
- **后台页面恢复（仅地址栏手动访问）**：`admin.html`、`assets/css/admin.css`、`assets/js/admin.js` 已恢复。前台 `index.html` / `app.js` 仍然**没有任何入口、链接或提示**，只能直接输入 `/admin.html` 打开；`robots.txt` 有 `Disallow: /admin.html`，后台页面带 `noindex, nofollow`。登录后可以查看 KPI、8 机体分布、四维平均、16 题选项分布、14 天趋势和答卷记录表，支持筛选、刷新、导出 CSV / JSON、删除单条；看板表格还支持「查看」单份答卷的逐题答案详情（兼容旧版记录，可复制该条 JSON）。`supabase` 模式用 Supabase 邮箱账号登录；`local` 模式不用登录；`custom` 模式只显示未配置提示。
- **缓存参数**：`index.html` 与 `admin.html` 里 CSS / JS 引用统一升到 `?v=2.3`（本次更新 v2.1 题库，避免旧 questions.js 缓存）。
- **数据库不变**：`ai_personality_responses` 表结构、RLS 策略都不变，**不需要重跑 `schema.sql`**。新版匹配元数据（`profileCode`、并列候选、距离）放在原有 `percents` 这个 jsonb 列里的 `percents.match` 下。
- **图片**：8 张人物插画已转成 `assets/img/m01.webp`–`m08.webp`（900×900）和 `assets/img/thumbs/m01.webp`–`m08.webp`（420×420），不再引用 `resources/` 里的原图；首屏不加载这些图。
- **分享链接**：新版为 `?type=<slug>`（如 `?type=machine-soul`）；旧版 `?result=EWSP` 这类链接会显示「旧版 16 型结果已经下线」的提示。

## 第 1 步：本地预览与自测

### 1.1 起本地服务器

```powershell
cd D:\xiaopaLLL\MBAItest
node tests/serve.mjs 8000
# 浏览器打开 http://127.0.0.1:8000/
```

- 必须用 http 服务器预览，**不要双击 `index.html` 用 `file://` 打开**：Supabase 提交会被跨域限制拦掉，测不出真实数据链路。
- 这个命令读取的是 `config.js` 里的线上 Supabase 配置，**本地每提交一份答卷都会写进线上库**。只想看界面、不想写数据时改用：

```powershell
node tests/serve.mjs 8000 --force-local
```

预览完回到 PowerShell 按 `Ctrl+C` 停止服务器。

### 1.2 逐条跑测试

测试脚本会自己起临时服务器，前台 E2E 和后台 local E2E 使用 `--force-local` 把数据锁在本地，**不会写线上数据库**；后台 E2E 的 Supabase 部分只打开登录页检查，不会真的登录。

```powershell
node tests/engine.test.mjs   # 计分引擎 + 数据层 + 后台 API / CSV（26 项）
node tests/smoke.mjs         # 静态资源 / 页面约定 / 文档关键词（42 项）
node tests/e2e.mjs           # 前台 headless Chrome 全流程（38 项）
node tests/admin-e2e.mjs     # 后台 headless Chrome：local 看板 64 项 + Supabase 登录页 8 项（72 项）
```

- `engine.test.mjs`：16 题结构、主维度 + 次要分与补偿下调、四维极值 −8 ~ +8、8 机体距离匹配、记录字段、`Store.admin` 与 `toCSV`；不联网，几秒跑完。
- `smoke.mjs`：检查前台与后台页面、脚本、样式、8 张图片、文档文件都能访问；检查没有外部 CDN、前台没有后台入口、后台页面关键容器齐全、前台不泄漏 M01–M08 或四字母代号；还会检查文档关键词是否齐全。改过文档的话一定要跑它。
- `e2e.mjs`：真实浏览器从头答完 16 题，验证结果页、分享页、旧链接提示、全中性并列；本机需要 Chrome 或 Edge。找不到浏览器时会提示并跳过（退出码 0）。
- `admin-e2e.mjs`：真实浏览器打开后台页面，验证 local 模式的看板 / KPI / 图表 / 筛选 / 单份答卷详情 / 删除 / 转义，以及 Supabase 配置下登录页正确出现；同样需要 Chrome 或 Edge，找不到会跳过。
- 具体通过数量以本机输出为准；只要最后一行是「全部通过」，就可以继续。
- 也可以一次跑完（依次 engine → smoke → e2e → admin-e2e）：

```powershell
npm.cmd test
```

如果 PowerShell 报「无法加载文件 …npm.ps1，因为在此系统上禁止运行脚本」，用 `npm.cmd test`，或者直接执行上面的 `node` 命令即可。

需要 Chrome/Edge：

```powershell

```

截图输出到 `tests/screenshots/`，已 gitignore，不会提交。

## 第 2 步：提交

### 2.1 暂存改动

```powershell
git status          # 先看一眼都有什么改动
git add -A
git status          # 再确认一次：该有的新增 / 修改 / 删除都在，resources/ 不在
```

- `git add -A` 会同时暂存新增、修改和删除，`deploy/` 旧脚本的删除也会一起进本次提交；恢复的 `admin.html` 等后台文件会显示为修改 / 新增。
- `resources/` 被 `.gitignore` 忽略，不会被 `git add -A` 加进来。
- 提交前确认 `git status` 里没有你不想发布的临时截图、测试产物或私密配置；不需要的删掉，或者补进 `.gitignore`。

补充：早期提交里已经跟踪过 `tests/screenshots/*.png`，`.gitignore` 对已经跟踪的文件无效，它们可能会以 `M`（已修改）出现。如果不想再提交截图，可以先从索引里移除（本地文件保留）：

```powershell
git rm --cached tests/screenshots/*.png
```

### 2.2 提交

```powershell
git commit -m "更新协作机体测试：首页简化、恢复数据后台"
```

想多看一眼改了哪些文件，可以用：

```powershell
git diff --cached --stat
```

如果提示 `nothing to commit`，说明没有实际改动或还没 `git add`。

## 第 3 步：推送到 GitHub

```powershell
git push origin main
```

- 第一次推送会弹浏览器让你登录 GitHub 授权；如果命令行要求密码，需要使用 GitHub Personal Access Token（在 GitHub → Settings → Developer settings 里生成），不要输入账号密码。
- 如果提示被拒绝（`non-fast-forward`，远端有你本地没有的提交），先同步再推：

```powershell
git pull --rebase origin main
git push origin main
```

- 推送完成后确认：

```powershell
git log --oneline -3
git status
```

`git status` 应显示 working tree clean；`git log` 第一条就是刚才的提交。

## 第 4 步：GitHub Pages 自动发布

GitHub Pages 在 `main` 分支有新提交后会自动重新发布，**不需要手动构建**。

### 4.1 确认 Pages 配置（只需确认一次）

打开仓库 <https://github.com/xiaopaLLL/ai-personality> → **Settings → Pages**：

- **Build and deployment → Source**：`Deploy from a branch`
- **Branch**：`main`，目录 `/ (root)` → **Save**

当前仓库应已是这个配置；如果之前改过，改回来后保存即可。

### 4.2 观察发布进度

- 仓库顶部 **Actions** 标签 → 左侧 workflow **`pages build and deployment`** → 看最新一次 run 是否出现绿色对勾。
- 也可以打开仓库的 **Deployments**（地址形如 `https://github.com/xiaopaLLL/ai-personality/deployments`），能看到最近一次 `github-pages` 部署记录。
- 一般 1–3 分钟完成，偶尔需要更久；期间线上可能仍是旧版本。

### 4.3 判断新版本已经生效

- 打开 <https://xiaopalll.github.io/ai-personality/>，按 `Ctrl+F5` 强制刷新（或开一个无痕窗口）。
- 新版特征：首屏是暗绿 + 荧光绿档案风、**8 个机体名称的文字目录（不加载人物图片）**、信息条是「16 道情境题 / 4 个维度 / 8 种协作机体」；页面源码里 CSS / JS 引用带 `?v=2.3`。
- 再验证两条：`https://xiaopalll.github.io/ai-personality/?type=machine-soul` 能打开分享页；`https://xiaopalll.github.io/ai-personality/?result=EWSP` 显示旧版链接下线提示。
- 后台页面：`https://xiaopalll.github.io/ai-personality/admin.html` 能打开登录页（不是 404），同时前台首页没有任何进入后台的入口。
- 如果强刷后仍是旧页面：确认 Actions 构建完成，再等几分钟（GitHub Pages 有 CDN 缓存）；仍不行就检查这次推送是否真的带上了 `index.html` 的改动。

### 6.1 数据后台页面（/admin.html）

1. 浏览器地址栏直接打开 `/admin.html`（线上是 `https://xiaopalll.github.io/ai-personality/admin.html`，本地预览是 `http://127.0.0.1:8000/admin.html`）。前台首页没有任何入口，只能手动输入地址。
2. 登录账号来自 Supabase：**Authentication → Users** 里创建的邮箱账号；没有账号就先 **Add user** 创建并确认邮箱。
3. 登录后看板包含：
   - 状态条：数据源 / 问卷版本 / 登录账号 / 已载入条数；
   - KPI：总答卷、今日新增、新版答卷、完成答卷率、平均用时、并列答卷数；
   - 8 机体分布（中文名 + M01–M08 内部编号，点击可筛选表格）；旧版 16 型数据在单独的「旧版类型」区域（当前版本范围有旧记录时才显示）；
   - 四维平均、16 题选项分布（折叠）、最近 14 天趋势；
   - 答卷记录表：时间 / 版本 / 结果 / 昵称 / 用时 / 标记 / 设备 / 查看 / 删除；默认读取最近 1,000 条，表格最多显示 500 行。
4. 常用操作：刷新；按版本（全部版本 / V1 全部 / v1.0 / V2 全部 / v2.0 / v2.1，默认 V2 全部）、时间范围、机体筛选；点「查看」（或点整行）打开单份答卷详情（逐题答案、四维百分比与原始分、匹配元数据、复制 JSON）；导出 CSV / 导出 JSON；删除单条（二次确认，不可恢复，删前先导出）；退出登录。
5. 模式说明：
   - `backend: 'supabase'`（当前线上）：必须登录；会话过期（401）会自动回到登录页；登录后看不到数据（403）通常是 RLS 的 `auth_can_read` 策略缺失，删不了多半是 `auth_can_delete` 缺失，见 `supabase/schema.sql`。
   - `backend: 'local'`：不需要登录，只显示当前浏览器 localStorage 里的记录（顶部有「本地模式」提示）。
   - `backend: 'custom'`：后台暂不支持，只显示未配置提示。
6. 后台页面带 `noindex`，`robots.txt` 也 `Disallow: /admin.html`；这只影响搜索引擎收录，不影响地址栏手动访问。

### 6.2 Supabase 控制台 Table Editor 看明细

1. 打开 <https://supabase.com/dashboard>，进入项目 `pcwlaykrepvdvzgrtktp`。
2. 左侧 **Table Editor** → 选表 `ai_personality_responses`。
3. 点 `created_at` 列头倒序；点某一行可以在右侧看到 `scores`、`percents`、`answers` 等 JSON 内容。
4. 只看新版数据：筛选 `survey_version` = `v2.1`。
5. 区分新旧：`survey_version` 是版本号，`result_code` 为 `M01`–`M08` 的是新版；旧版 16 型的记录（四字母代码 / 旧名称）仍保留在表里，正常现象。

### 6.3 SQL Editor 做统计

左侧 **SQL Editor → New query**，粘贴后点 **Run**：

```sql
-- 1) 新版各机体作答数
select result_code, result_name, count(*) as responses
from public.ai_personality_responses
where survey_version = 'v2.1'
group by 1, 2
order by 3 desc;

-- 2) 并列 / 同时接近的答卷（新版才有 percents.match）
select created_at,
       result_name,
       percents->'match'->>'candidates'   as candidates,
       percents->'match'->>'tie'          as tie,
       percents->'match'->>'near'         as near,
       percents->'match'->>'bestDistance' as best_distance
from public.ai_personality_responses
where survey_version = 'v2.1'
  and (percents->'match'->>'tie')::boolean
order by created_at desc
limit 50;

-- 3) 新旧版本数据量对比
select survey_version, count(*) as responses
from public.ai_personality_responses
group by 1
order by 2 desc;
```

- 数据后台页面用登录账号读取 / 删除；Supabase 控制台登录账号也有读权限；匿名访客的 anon key 只有 insert 权限，所以前台拿不到数据。
- 表结构没有变化，**不需要重跑 `schema.sql`**。只有新建了 Supabase 项目、或表被删掉时，才需要把 `supabase/schema.sql` 全选粘贴到 SQL Editor 执行一次。

## 常见问题

| 症状 | 处理 |
| --- | --- |
| Pages 没更新 / 线上还是旧版本 | ① 确认 `git push origin main` 成功、`git status` 干净；② 仓库 Actions → `pages build and deployment` 最新一次是否绿色完成；③ 再等几分钟并 `Ctrl+F5` 强刷 / 无痕窗口；④ 确认 Settings → Pages 仍是 `main` / `(root)`。 |
| 图片 404 | 确认 `assets/img/`（含 `thumbs/`）已提交：`git ls-files assets/img` 能列出来；文件名必须是小写 `m01.webp`，线上区分大小写；确认页面里是相对路径 `assets/...`；`.nojekyll` 没被删。 |
| 分享链接前缀不对（变成 localhost 或旧地址） | 改 `config.js` 里的 `site.publicUrl` 为 `https://xiaopalll.github.io/ai-personality/`（末尾保留 `/`），`git add` → `git commit` → `git push` 后重新复制链接。 |
| 首页看不到人物图片 | 正常：首屏是纯文字机体目录，不加载图片；人物插画只在结果页、并列候选、对照机体和分享落地页出现。 |
| 找不到数据后台入口 | 正常：前台不提供入口，直接在地址栏输入 `/admin.html`；后台页面带 `noindex`、`robots.txt` 也禁止收录，但可以手动访问。 |
| 后台登录失败 | ① Supabase → Authentication → Users 里有没有账号、邮箱是否已确认；② 邮箱 / 密码是否输错；③ `config.js` 的 `supabase.url` 与 `anonKey` 是否来自同一个项目；④ `backend` 是否为 `'supabase'`（`local` 模式后台不用登录，`custom` 模式后台不支持）。 |
| 后台提示登录已过期 / 401 | 会话过期会自动回到登录页，重新登录即可；后台会自动尝试刷新 token，刷新失败时需重新登录。 |
| 后台能登录但看不到数据 / 403 | RLS 权限问题：`authenticated` 角色需要 `select`（`auth_can_read`）才能读，删除还需要 `delete`（`auth_can_delete`）。按 `supabase/schema.sql` 检查策略，修好后重新登录并刷新。 |
| 后台删除失败 | 多半是缺少 `auth_can_delete` 删除策略；删除不可恢复，操作前先导出 CSV / JSON 备份。 |
| 后台显示「自定义接口模式，未配置」 | 后台只支持 `supabase` 与 `local` 两种模式；需要后台看数据时把 `config.js` 的 `backend` 改回 `'supabase'`。 |
| Supabase 写入失败 / 数据没进表 | ① 浏览器开发者工具 Network 里看 `POST /rest/v1/ai_personality_responses` 的返回：401 多半是 anon key 复制不完整或项目不对，404 多半是表名 / URL 错误，403 多半是 RLS 策略缺失；② 核对 `config.js` 的 `supabase.url`、`anonKey`、`table` 是否和 Supabase 项目一致；③ RLS 的匿名 insert 策略需要存在（见 `supabase/schema.sql`），表结构没变时**不要**重跑脚本；④ 网络失败时记录会暂存在访客浏览器 `localStorage`（`aipt:pending:v2`），下次打开页面会自动补传，可让访客重开页面再验证。 |
| 浏览器缓存导致还是旧 JS/CSS | 强刷 `Ctrl+F5` 或换无痕窗口；如果用手机，清一下浏览器缓存。改过 js/css 的话，记得升 `index.html` / `admin.html` 里对应资源的 `?v=` 参数（例如 `?v=2.3` → `?v=2.4`）再重新部署。 |
| PowerShell 里 `npm test` 报「禁止运行脚本」 | 用 `npm.cmd test`，或直接 `node tests/engine.test.mjs` / `node tests/smoke.mjs` / `node tests/e2e.mjs` / `node tests/admin-e2e.mjs`。 |
| 本地预览把测试数据写进了线上库 | 预览时改用 `node tests/serve.mjs 8000 --force-local`；已经写入的记录可以在 `/admin.html` 里删除（或去 Supabase 控制台按 `created_at` / `user_agent` 删除）。 |
| `node tests/e2e.mjs` / `node tests/admin-e2e.mjs` 说找不到浏览器 | 安装 Chrome 或 Edge；或跳过这些测试，其它测试仍然有效。 |
| 改了文档导致 `smoke.mjs` 失败 | 冒烟测试会检查文档关键词（如 README 的「GitHub Pages」「Supabase」「重新部署」「resources/」），按失败提示把对应词补回文档即可；不要为了通过测试去删测试断言。 |
| 想改题库但怕改坏 | 只动 `assets/js/questions.js`，保持 16 题 / 4 维 / 每题 3 个选项 / 每题声明 `dim` 主维度；三个选项在主维度上是一正、一负、一中性（`+2` 或 `+1` / `-2` 或 `-1` / `0`），次要维度只能 `±1`、每个选项最多一个且与主维度不同；加次要分后必须做补偿下调，保证每维理论极值仍是 −8 ~ +8。改完升 `meta.version` 和 `index.html` / `admin.html` 里的 `?v=`，跑 `node tests/engine.test.mjs`。 |

## 回滚

如果新版上线后发现严重问题，可以回到上一个版本。**推荐用 `git revert`**，不破坏提交历史。

### 方式一：revert 某次提交（推荐）

```powershell
git log --oneline -10          # 找到要回滚的那次提交（例如最新提交）
git revert <commit-hash>       # 生成一条反向提交；有冲突按提示解决后 git revert --continue
git push origin main
```

推送后 GitHub Pages 会按回滚后的内容重新发布，1–3 分钟后强刷验证。

### 方式二：reset 回旧提交后强推（风险更高，单人仓库再用）

```powershell
git log --oneline -10
git reset --hard <旧提交的-hash>
git push --force-with-lease origin main
```

- 这会改写远端历史，多人协作时不要用；`--force-with-lease` 比 `--force` 安全，但如果远端在你 fetch 后又有新提交，它会拒绝推送。
- 强推后本地改动会丢失，操作前先确认没有未提交的内容（`git status`）。

### 数据库不需要回滚

- 前端回滚不会删除已经写入 Supabase 的记录；新版和旧版数据共用一张表，靠 `survey_version` / `result_code` 区分。
- 如果确实要清理某批测试数据：登录 Supabase 控制台 → SQL Editor 先 `select` 确认范围，再执行带明确 `where` 条件的 `delete`（例如按 `created_at` 时间段或 `user_agent`）；删除前先导出备份，DELETE 不可恢复。
- 不需要为了回滚去重跑 `schema.sql`。

### 回滚后验收

- [ ] 线上恢复为回滚版本的行为（例如结果页样式 / 分享链接形式），`Ctrl+F5` 确认不是缓存。
- [ ] Pages Actions 最新一次部署是绿色。
- [ ] 如需保留用户已答数据，确认表数据没有因回滚误删。

## 可选：换域名 / 换仓库名

### 换自定义域名

1. 在域名服务商处配置解析：
   - 子域名（推荐，如 `test.example.com`）：加 CNAME 记录，值 `xiaopaLLL.github.io`。
   - 顶级域名：加 4 条 A 记录，值 `185.199.108.153`、`185.199.109.153`、`185.199.110.153`、`185.199.111.153`。
   - DNS 托管在 Cloudflare 时，先关掉橙色云朵（DNS only），等 GitHub 签好 HTTPS 证书再按需开启。
2. 仓库根目录新建文件名就叫 `CNAME`（无扩展名）的文件，内容只有一行你的域名。
3. 仓库 Settings → Pages → Custom domain 填入域名 → Save，等 DNS check 通过后勾选 **Enforce HTTPS**。
4. 把 `config.js` 的 `site.publicUrl` 改成 `https://你的域名/`，提交推送。
5. 按第 5 步验收清单重新验收分享链接。

### 换仓库名

- 线上地址会变成 `https://xiaopaLLL.github.io/<新仓库名>/`；同步改 `config.js` 的 `site.publicUrl`，本地远端也要更新：

```powershell
git remote set-url origin https://github.com/xiaopaLLL/<新仓库名>.git
git remote -v
```

- 旧分享链接里的前缀不会自动跟着变，需要用户重新复制新链接；不要依赖旧地址长期可用。
